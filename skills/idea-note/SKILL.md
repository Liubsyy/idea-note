# Idea Note 笔记助手

让通用 AI 助手能够编写 Idea Note 支持的笔记扩展。普通 Markdown、数学公式和 Mermaid 沿用已有能力；这里补充应用特有的组件协议和高亮块。

## 使用环境与文件操作

- 使用当前 AI 环境实际提供的文件读取、搜索、编辑工具。读取目标笔记后再修改，局部修改优先保留其余内容。
- 当前笔记和笔记工作区以用户提供的路径或宿主明确附加的上下文为准；当前代码仓库不一定是用户的笔记库。没有目标文件上下文时，可以直接交付可粘贴的 Markdown。
- 本 Skill 提供写法和工作流程，不会注册工具，也不会连接 Idea Note 的编辑器。如果宿主提供 `component_guide`，先用 `topic=overview` 获取规范及当前运行器状态，需要时再取具体主题；没有该工具就按下文读取随附参考文件。
- 只有宿主真的提供相关工具时，才能使用 `read_open_file`、`edit_open_file`、`write_open_file`、`read_file`、`search_notes`、`create_note`、`delete_file`。不要把这些名称当成通用 AI 环境内置能力。
- 通过磁盘工具修改文件会写入磁盘，不等于只修改 Idea Note 的编辑器缓冲区。不要声称已同步未保存的编辑器内容、控件当前值或运行结果。
- 组件控件、自动运行和行内结果需要由 Idea Note 渲染。普通 Markdown 编辑器和聊天界面可能只显示源码。

## 编写可交互组件

用户希望在笔记里调参数、重算图表、转换数据或刷新看板时，生成完整的组件 Markdown。一个组件由可选的 `input` 参数块和一个可运行代码块组成。

先读 [组件速览](references/overview.md)，按任务补充相关参考，不必一次加载全部文档：

| 任务 | 参考 |
| --- | --- |
| 声明滑块、数字、文本、布尔、下拉、文件、日期时间控件 | [参数块](references/input.md) |
| 读取参数、笔记表格、CSV / JSON / 文本文件 | [数据绑定](references/data.md) |
| 返回 Markdown、表格、JSON、Mermaid、HTML、图片或动态类型 | [输出协议](references/output.md) |
| 选择语言、自动触发、工作目录、超时或排查不运行 | [运行环境](references/run.md) |
| 需要完整代码样例 | [组件示例](references/examples.md) |

按以下约束实现：

1. 确定用户调什么、数据来自哪里、结果显示成什么。每个运行块只有一个 `in=` 来源；需要参数与文件组合时，把 `file` 字段放进同一个 `input` 块。
2. 优先使用已知启用且已安装解释器的语言。没有宿主运行器状态时可优先生成标准库 Python 版本，说明运行需要在 Idea Note 启用对应运行器且设备已安装解释器；不要把本次终端里可用的解释器当成应用配置已验证。
3. 参数使用 `IDEA_NOTE_INPUT` 的 JSON 或同名环境变量传入，不能依赖 stdin、浏览器 DOM 或脚本源码替换。布尔值优先从 JSON 读，避免把字符串 `"false"` 当成真值。
4. 固定输出类型时声明 `out=类型`，stdout 最后一个非空行输出该类型数据的**单行合法 JSON**。字符串也要 JSON 编码；Python 用 `json.dumps`，Node 用 `JSON.stringify`，不要输出缩进多行 JSON。
5. `out=auto` 输出 `{"idea_note_result":{"type":"类型","data":数据}}` 包装对象。`out=table` 的 `rows` 必须是二维数组，各行长度等于 `columns` 长度；不要把输入表格的对象行直接当输出表格。
6. 纯计算组件需要随参数重算时用 `run=watch`；需要首次打开也计算时用 `run=watch+open`。按钮型操作用 `run=manual` 或省略。`watch` 只监听绑定的 `input` 控件，不监听表格或文件变化。
7. `out=html` 是消毒后的静态 HTML，不能用 `<script>`、内联事件或 HTML 表单实现交互；交互放在 `input` 块，通过重算生成结果。
8. 为参数、空日期、零除和空数据设置合理默认值及必要处理。组件标识保持唯一；同一笔记中源码完全相同的运行块会共享结果，独立组件可用不同注释区分源码。

## 执行与交付

代码以用户权限在本机执行，工作目录通常为笔记所在目录。默认编写计算和渲染逻辑。用户需要的文件、网络或其他外部操作应限于明确的任务范围，有副作用的动作使用手动运行，避免打开笔记或拖动参数就重复执行；不要擅自安装依赖或获取凭证。

优先标准库；确需第三方库时，在笔记正文说明依赖。生成图片要先创建真实文件再返回路径，并选择组件自己的输出文件名，避免覆盖用户已有文件。无需生成图片文件时，可考虑直接返回静态 SVG / HTML 或 Mermaid。

有本地工具且适合验证时，检查参数块能被解析、`in` 和 `id` 一致、脚本默认值及关键边界可执行、结果符合所声明的协议。若只能生成文本，明确未在 Idea Note 内验证，不要声称已运行。

参数修改和行内运行结果默认仅在内存中，不会自动保存进 `.md`。用户要求保存参数时，可以修改源码默认值，或说明应用里的「固化为默认值」操作；要保留结果供普通 Markdown 阅读，需明确写成静态正文或输出文件。

写入目标笔记时，直接插入 `input` 和运行块，不要再套外层代码围栏。通过聊天交付可复制源码时，可用四个反引号包裹整段 Markdown，保留内部三个反引号的代码块。

## 高亮块

新增或整体重写高亮块时，标记独占引用块首行，标记后保留一条仅含 `>` 的空白引用行，块内每行都带引用前缀：

```markdown
> [!HIGHLIGHT color=blue]
>
> **注意事项**
>
> - 可以包含列表、链接等 Markdown。
```

颜色支持 `yellow`、`blue`、`green`、`red`、`purple` 及六位十六进制值；省略 `color` 默认为蓝色。兼容读取没有空白引用行的旧格式，编辑时保留原有颜色，除非用户要求更改。

# 可交互组件规范

> 这篇文档讲清楚一件事：怎样在 Idea Note 的普通 Markdown 笔记里，写出一个「能调参数、会自动重算、结果直接显示在笔记里」的小工具。
>
> 全文按「先看懂 → 声明参数 → 喂数据 → 拼出代码块 → 控制运行 → 输出结果」的顺序展开，每一节都建立在上一节之上，建议第一次阅读时按顺序看。只想抄现成案例的话，去看 [可交互组件例子.md](./可交互组件例子.md)。

---

## 1. 可交互组件是什么

### 1.1 一句话解释

可交互组件 = **一个参数块 + 一段可运行代码**。

读者在笔记里拖动滑块、改数字、选下拉框，你写的脚本就在本机重新跑一遍，把新结果渲染回笔记里。整个过程不用离开笔记，也不用启动任何服务。

它由两种围栏代码块组成：

| 块类型 | 作用 |
| --- | --- |
| `input` 参数块 | 声明有哪些参数，在预览里显示成输入框、复选框、下拉框、滑块 |
| 可运行代码块 | 读取参数（或表格、文件），在本机执行脚本，把输出渲染成文本、表格、图表、图片等 |

两者可以搭配使用，也可以只写一个可运行代码块（这时它就是一个「点一下就出结果」的按钮）。

### 1.2 一分钟看懂：一个完整的最小组件

下面这个组件声明了「数量」和「单价」两个参数，用户一改动，Python 就重新算一遍总价：

````markdown
```input {id=price_calc}
quantity: number = 2    {min: 1, step: 1, label: 数量, unit: 件}
price:    number = 9.90 {min: 0, step: 0.01, label: 单价, unit: 元}
```

```python {in=price_calc, out=markdown, run=watch}
import json
import os

quantity = int(float(os.environ["quantity"]))
price = float(os.environ["price"])
result = f"**合计：{quantity * price:.2f} 元**"

print(json.dumps(result, ensure_ascii=False))
```
````

拆开看，四个属性各管一件事：

- `id=price_calc`：给参数块起个名字，方便被引用。
- `in=price_calc`：这段代码要用那个参数块的值。
- `out=markdown`：我会输出一段 Markdown，请按 Markdown 渲染。
- `run=watch`：参数一变就自动重跑。

### 1.3 数据是怎么流动的

```text
用户在控件里改了值
  ↓
值被写成环境变量 quantity / price（同时还有一份完整 JSON）
  ↓
脚本在你自己的电脑上真实执行
  ↓
系统只看 stdout 的「最后一个非空行」
  ↓
按 out=markdown 校验这行是不是合法 JSON 字符串
  ↓
渲染成结果卡片，显示在代码块旁边
```

这条链路里有两个新手最容易踩的点，先在这里点名，后面会详细讲：

1. **传进来的是环境变量**，所以脚本要用 `os.environ` / `process.env` 去读（第 4 节）。
2. **传出去的必须是一行合法 JSON**，所以上面示例里才有 `json.dumps`——直接 `print("...")` 是不行的（第 7 节）。

### 1.4 先说清楚三条边界

这三条决定了可交互组件「能做什么、不能做什么」，越早知道越好：

- **代码是在你本机真实执行的**，不是浏览器沙箱。它有你账号的全部权限，所以只运行你信任的笔记（第 8 节）。
- **参数值和运行结果默认只活在内存里**，不会自动写回 `.md` 文件，也不会产生 Git 差异（第 3.8 / 7.6 节）。
- **它不是能跑任意 JavaScript 的网页组件**。交互能力只有三种：参数控件、自动重算、结果表格排序；`out=html` 只渲染消毒后的静态 HTML。

## 2. 语法总览

这一节给出一张地图：围栏怎么写、属性有哪些。每个属性的细节留到对应章节展开。

### 2.1 围栏怎么写

支持三个或更多反引号，也支持三个或更多波浪号。收尾围栏必须用**同一种字符**，且长度不能比开头短。

````markdown
```python {out=text}
print('"hello"')
```

~~~~python {out=text}
print('"hello"')
~~~~
````

围栏第一行（信息行）的通用形式是：

```text
<语言> {<属性>, <属性>, ...}
```

例如：

```text
python {in=params, out=table, run=watch+open, result=below}
```

解析规则：

- 语言标识必须写在最前面，匹配时不区分大小写。
- 属性必须包在一对完整的 `{}` 里，属性之间用**英文逗号**分隔。
- 属性写成 `key=value`；只有 `watch` 允许写成不带值的裸标志。
- 属性名不区分大小写；枚举值按小写识别，建议照本文写法照抄。
- 属性值里可以有空格，例如 `in=table:销售 数据`。
- **不支持用引号把逗号转义**，所以名称、路径、值里不要出现英文逗号。
- 认不出来的属性会被静默忽略。
- 如果 `{` 没有配对的 `}`，整组属性会被丢弃，这个块退化成一个普通的可运行代码块。

### 2.2 属性总表

| 属性 | 写在哪 | 取值 | 默认 | 作用 | 详见 |
| --- | --- | --- | --- | --- | --- |
| `id` | `input` 块 | 标识符 | 无 | 给参数块起名，供 `in=` 引用 | 3.2 |
| `in` | 可运行块 | `<id>` / `table:<名称>` / `file:<路径>` | 无 | 数据从哪来 | 4 |
| `out` | 可运行块 | `text` `table` `json` `mermaid` `html` `image` `markdown` `auto` | 未声明 | 结果是什么类型、怎么渲染 | 7 |
| `run` | 可运行块 | `manual` `watch` `open`，可组合 | `manual` | 什么时候自动运行 | 6.3 |
| `watch` | 可运行块 | 裸标志 / `true` / `false` | 无 | `run=watch` 的老写法 | 6.3 |
| `result` | 可运行块 | `above` / `below` | `above` | 结果显示在代码块上方还是下方 | 7.5 |

### 2.3 建议的书写顺序

为了让别人一眼看懂，建议统一按这个顺序写：

```text
语言 {id=..., in=..., out=..., run=..., result=...}
```

`id` 基本只用在 `input` 块上；`in` / `out` / `run` / `result` 用在可运行代码块上。

## 3. 声明参数：`input` 参数块

参数块决定了读者能调什么。它不执行任何代码，只负责「长出控件」和「保管当前值」。

### 3.1 基本结构

````markdown
```input {id=<块标识>}
<字段名>: <字段类型> = <初始值> {<字段选项>}
<字段名>: <字段类型> = <初始值> {<字段选项>}
```
````

一行一个字段。空行、以及以 `#` 或 `//` 开头的**整行**注释会被忽略。

一个用满了五种类型的例子：

````markdown
```input {id=profile}
# 基本资料
age:        number = 28 {min: 0, max: 150, step: 1, label: 年龄, unit: 岁}
nickname:   text   = "小明" {label: 昵称}
subscribed: bool   = true {label: 接收通知}
level:      select = [初级, 中级, 高级] {default: 中级, label: 等级}
data_file:  file   = "./data.csv" {as: csv, label: 数据文件}
```
````

### 3.2 给块起名：`id`

```text
id=<标识符>
```

- 第一个字符必须是英文字母或下划线；后续可以是字母、数字、下划线、连字符。
- 建议只用小写字母、数字和下划线，例如 `loan_calc`。
- 不写 `id` 的 `input` 块照样会显示控件，但**没法被代码块稳定引用**。
- 同一篇笔记里 `id` 要唯一。重名时当前实现取第一个匹配项，但不要依赖这个行为。

### 3.3 字段名的硬性要求

字段名必须匹配：

```text
^[A-Za-z_][A-Za-z0-9_]*$
```

也就是说：

- 首字符只能是英文字母或下划线，其余只能是字母、数字、下划线。
- 不能有连字符、空格、中文、点号或其他符号。
- 同一个块内不能重名。
- **字段名会直接变成环境变量名**，所以要避开 `PATH`、`HOME`、`SHELL` 这类系统变量。

合法：`amount`、`tax_rate`、`item2`、`_debug`
不合法：`tax-rate`、`2nd_item`、`总额`、`user.name`

想让界面显示中文？用 `label` 选项，见 3.5。

### 3.4 五种字段类型

| 类型 | 值的类型 | 控件 | 典型写法 |
| --- | --- | --- | --- |
| `number` | number | 数字输入框；配了 `slider` 再加一个滑块 | `amount: number = 100` |
| `text` | string | 单行文本框 | `title: text = "报告"` |
| `bool` | boolean | 复选框 | `enabled: bool = true` |
| `select` | string / number / boolean | 下拉框 | `years: select = [10, 20, 30]` |
| `file` | string | 单行路径输入框 | `data: file = "./data.csv" {as: csv}` |

#### `number`

```text
amount: number = 100 {min: 0, max: 1000, step: 10, label: 金额, unit: 元}
score:  number = 80  {slider: 0..100, step: 1, label: 分数}
```

- 初始值必须能转成有限数字；不写初始值按 `0` 处理。
- `min` / `max` 会约束最终提交的值，越界的默认值也会被夹回范围内。
- 输入过程中**不会立刻截断**——否则你想输 `50000`，刚打出的 `5` 就被改写了；失焦或提交后才按范围校正。
- `step` 会同时作用于数字框和滑块；不写时数字框用浏览器默认步长。
- `slider: a..b` 一次性设置滑块、`min=a`、`max=b`。
- `slider: true` 只是显示滑块；没设范围时滑块默认按 `0..100`、步长 `1` 显示。

#### `text`

```text
title: text = "月度报告" {label: 标题}
note:  text = 未分类
```

- 双引号、单引号、不加引号都行，解析时只剥掉最外层的一对相同引号。
- 字段 DSL **没有通用的字符串转义**，所以不适合写包含逗号等分隔符的复杂文本。
- 控件是单行文本框，没有多行文本域。

#### `bool`

```text
enabled:  bool = true  {label: 启用}
archived: bool = false {label: 已归档}
```

- 建议只写小写 `true` / `false`。
- 传给脚本时，环境变量里是字符串 `"true"` / `"false"`，完整 JSON 里是真正的布尔值（见 4.1）。

#### `select`

```text
years: select = [10, 20, 25, 30] {default: 30, label: 年限, unit: 年}
theme: select = [浅色, 深色, 跟随系统] {default: 跟随系统, label: 主题}
```

- 等号右边必须是非空列表 `[...]`，选项用英文逗号分隔。
- 每个选项按字面量解析，可以是数字、布尔值或字符串。
- 不写 `default` 就默认选第一项；`default` 要能按字符串形式匹配上某个选项，否则回退到第一项。
- 不支持嵌套数组，也不能把「含英文逗号的字符串」当成一个选项。

#### `file`

```text
source: file = "./sales.csv" {as: csv, label: 销售数据}
config: file = "./config.json" {as: json, label: 配置}
readme: file = "./README.md" {as: text, label: 说明}
```

- 控件里存的是路径字符串。
- 路径相对**当前笔记所在目录**解析；也可以用绝对路径，但最终文件必须落在当前工作区内。
- 自动读取上限 **2 MB**。
- 文件不存在、读不了、超限、跑到工作区外、内容格式错——本次运行直接中止并报错。
- `as` 决定载入后的数据类型；不写或写了未知格式时按 `text` 处理（格式细节见 4.5）。

### 3.5 字段选项

选项写在行尾的 `{}` 里，用英文逗号分隔。`key: value` 和 `key = value` 都能用，推荐统一用冒号。

| 选项 | 适用类型 | 取值 | 默认 | 作用 |
| --- | --- | --- | --- | --- |
| `label` | 全部 | 文本 | 字段名 | 控件左侧的显示名称 |
| `default` | 全部（`select` 最常用） | 兼容的字面量 | 等号右边的初始值 | 覆盖初始值；`select` 用它指定默认选项 |
| `min` | `number` | 数字 | 无 | 最小值 |
| `max` | `number` | 数字 | 无 | 最大值 |
| `step` | `number` | 数字 | 浏览器默认；滑块为 `1` | 步进值 |
| `slider` | `number` | `true` 或 `<min>..<max>` | 不显示 | 加一个滑块；范围写法同时设置 `min`/`max` |
| `unit` | 全部 | 文本 | 空 | 控件右侧的单位后缀 |
| `as` | `file` | `csv` / `json` / `text` | `text` | 文件内容按什么格式解析 |

解析规则：

- 选项名不区分大小写，内部统一转小写。
- 认不出来的选项被忽略。
- `min` / `max` / `step` 解析不出数字时视为没写。
- `slider` 范围非法时不显示滑块（除非值恰好是 `true`）。
- `as` 非法时回退成 `text`。
- 同名选项重复出现时，后面的覆盖前面的。

### 3.6 偷懒写法：省略类型

类型可以不写，系统按初始值猜：

| 初始值长这样 | 猜成 |
| --- | --- |
| `[a, b, c]` | `select` |
| `true` / `false` | `bool` |
| 有限数字 | `number` |
| 其他或为空 | `text` |

```text
count = 10
enabled = true
color = [red, green]
title = "hello"
```

上面四行依次是 `number`、`bool`、`select`、`text`。

两个提醒：字段 DSL 只支持**整行**注释，别把 `# number` 这类说明追加到字段行末尾；正式文档里还是建议把类型显式写出来，含义更稳定，也更容易审查。

### 3.7 写错了会怎样

每行独立解析。**一行写错只会跳过这一行**，其他合法字段照常渲染。错误显示在参数卡片底部，格式是「第 N 行：错误原因」。

常见错误：

- 不符合 `名字: 类型 = 默认值 {选项}` 的结构；
- 用了未知类型；
- `number` 的初始值不是数字；
- `select` 没给出非空选项列表；
- 字段名重复。

### 3.8 当前值存在哪：重置与固化

理解这一点，才知道「读者调过的参数会不会被保存」：

- 用户改过的值存在**内存**里，按「文件路径 + 参数块 id」区分。
- 切换标签页时通常能保留；关闭文件、重启应用或清理状态后就不保证了。
- 拖滑块、敲文字**不会修改 Markdown**，不产生撤销记录，也不制造 Git 差异。
- **「重置」**：丢掉内存里的改动，回到文档里声明的默认值。
- **「固化为默认值」**：把用户实际改过的字段写回 Markdown。普通字段改写等号右边；`select` 保留选项列表，写入或更新 `{default: ...}`。
- 只读模式下控件禁用，也不显示「重置」和「固化」。

## 4. 输入：代码怎么拿到数据

参数块只是把值存了下来。这一节讲这些值（以及表格、文件）是怎么送进脚本的。

### 4.1 永远有两条通道

不管数据来自哪里，系统都会同时准备好：

1. **`IDEA_NOTE_INPUT` 环境变量**——一整份 JSON 字符串。它能保留数字、布尔、数组、对象的真实类型，是首选通道。
2. **一批独立环境变量**——方便脚本零依赖地读一个标量或路径。

（界面上还会显示一份输入快照和摘要，那只是给人看的，不是脚本接口。）

所以一个典型的读取姿势是：

```python
import json, os

payload = json.loads(os.environ["IDEA_NOTE_INPUT"])   # 有类型的完整输入
quantity = os.environ["quantity"]                      # 快捷的字符串读法
```

下面三节分别讲三种数据来源。一个代码块**只能有一个生效的 `in`**；重复书写时，按属性出现顺序由后一个覆盖前一个。

### 4.2 来源一：`input` 参数块（`in=<id>`）

````markdown
```input {id=params}
amount: number = 100
active: bool = true
name: text = "示例"
```

```python {in=params, out=json}
import json, os

typed = json.loads(os.environ["IDEA_NOTE_INPUT"])
result = {
    "amount_env": os.environ["amount"],
    "amount_typed": typed["amount"],
    "active_env": os.environ["active"],
    "active_typed": typed["active"],
}
print(json.dumps(result, ensure_ascii=False))
```
````

`IDEA_NOTE_INPUT` 的形态就是字段名到值的直接映射：

```json
{
  "amount": 100,
  "active": true,
  "name": "示例"
}
```

两条通道里的值有细微差别，对照表：

| 字段类型 | 独立环境变量 | `IDEA_NOTE_INPUT` 里 |
| --- | --- | --- |
| `number` | 十进制字符串，如 `"100"` | JSON number |
| `text` | 原文本 | JSON string |
| `bool` | `"true"` / `"false"` | JSON boolean |
| `select` | 所选值的字符串形式 | 保留选项原本的 JSON 基本类型 |
| `file` | 解析后的绝对路径 | 字段名对应绝对路径，另有 `<字段名>_data` 存内容 |

`file` 字段比较特殊，它一个字段会生出四个入口：

| 名称 | 内容 |
| --- | --- |
| `<字段名>` 环境变量 | 绝对文件路径 |
| `<字段名>_path` 环境变量 | 同一个绝对路径 |
| `IDEA_NOTE_INPUT[<字段名>]` | 同一个绝对路径 |
| `IDEA_NOTE_INPUT[<字段名>_data]` | 按 `as` 解析后的内容 |

字段名为 `source` 时：

```python
path = os.environ["source_path"]
payload = json.loads(os.environ["IDEA_NOTE_INPUT"])
data = payload["source_data"]
```

**顺带一个坑：这些名字不能被占用。** 为避免覆盖协议变量或其他字段生成的辅助键，字段名不要叫：

- `IDEA_NOTE_INPUT`
- `table_rows`
- `file_path`
- `_truncated`
- 别的文件字段已经生成的 `<字段名>_path` / `<字段名>_data`

比如已经有文件字段 `source`，就别再声明 `source_path` 或 `source_data`。当前实现按字段顺序组装输入，名字冲突时值可能被覆盖，不要依赖覆盖顺序。

### 4.3 来源二：Markdown 表格（`in=table:<名称>`）

表格的「名称」可以是它上方的 1～6 级标题，也可以是一行只写名称的普通文本。名称和表格之间允许有空行，但不能夹别的内容。

````markdown
### 销售数据

| 月份 | 金额 |
| --- | ---: |
| 1月 | 1200 |
| 2月 | 1580 |

```python {in=table:销售数据, out=json}
import json, os
data = json.loads(os.environ["IDEA_NOTE_INPUT"])
print(json.dumps(data, ensure_ascii=False))
```
````

这时 `IDEA_NOTE_INPUT` 的结构是：

```json
{
  "columns": ["月份", "金额"],
  "rows": [
    {"月份": "1月", "金额": "1200"},
    {"月份": "2月", "金额": "1580"}
  ],
  "table": [
    {"月份": "1月", "金额": "1200"},
    {"月份": "2月", "金额": "1580"}
  ]
}
```

额外还有一个环境变量：

```text
table_rows=<数据行数>
```

几条要注意的：

- `rows` 和 `table` 内容完全相同，都是对象数组，用哪个都行。
- **所有单元格都是字符串**，要算数就自己转。
- 表格必须写成首尾都有竖线的形式：`| A | B |`。
- 第二行必须是合法分隔行，例如 `| --- | ---: |`。
- 当前的表格读取器很简单，按 `|` 切单元格，不处理单元格内转义竖线之类的复杂语法。
- 同名标题出现多次时用第一个匹配到的表格，别依赖重名。

### 4.4 来源三：直接绑定文件（`in=file:<路径>`）

````markdown
```python {in=file:./sales.csv, out=json}
import json, os
payload = json.loads(os.environ["IDEA_NOTE_INPUT"])
result = {
    "absolute_path": os.environ["file_path"],
    "row_count": len(payload["data"]),
}
print(json.dumps(result, ensure_ascii=False))
```
````

这时 `IDEA_NOTE_INPUT` 的结构是：

```json
{
  "path": "/absolute/workspace/path/sales.csv",
  "data": "按文件格式解析后的值"
}
```

另外还有：

```text
file_path=/absolute/workspace/path/sales.csv
```

这种写法没地方写 `as`，所以格式按扩展名自动判断（不区分大小写）：

| 扩展名 | 格式 |
| --- | --- |
| `.csv` | `csv` |
| `.json` | `json` |
| 其他或没有扩展名 | `text` |

### 4.5 文件内容按格式怎么解析

`file` 字段的 `as` 和 `in=file:` 的自动判断，最终都落到这三种格式上：

**`text`**：`data` 就是完整的文本字符串。

**`json`**：`data` 是 `JSON.parse` 之后的任意合法 JSON 值。语法错误会直接阻止代码运行。

**`csv`**：首行当字段名，后面每行转成一个对象。

```csv
product,qty,price
键盘,2,299
耳机,1,199
```

变成：

```json
[
  {"product": "键盘", "qty": "2", "price": "299"},
  {"product": "耳机", "qty": "1", "price": "199"}
]
```

CSV 解析支持：英文逗号分隔、双引号包裹字段、引号内的逗号和换行、两个连续双引号表示一个双引号、LF / CRLF / CR 三种换行。

注意：**所有值都保持字符串**；缺失的尾部单元格补空字符串；表头重复时后面的同名列会覆盖前面的。

### 4.6 数据太大时会被裁剪

`IDEA_NOTE_INPUT` 的完整 JSON 字符串不超过 **32 KiB** 时原样传入。超了就换成一个精简对象：

```json
{
  "_truncated": true,
  "保留下来的标量字段": "..."
}
```

精简规则：

- 保留字符串、数字、布尔值和 `null`；
- 删掉数组、对象这类大块内容；
- 文件路径仍然可以从独立的 `file_path` / `<字段名>_path` 环境变量拿到；
- 所以**处理大文件时应该照着路径自己读**，不要假设 `<字段名>_data` 一定在。

Python 里推荐这样先探一手：

```python
payload = json.loads(os.environ["IDEA_NOTE_INPUT"])
if payload.get("_truncated"):
    # 改从 *_path 环境变量读原文件
    pass
```

## 5. 可运行代码块结构

### 5.1 完整形态

````markdown
```python {in=params, out=markdown, run=watch, result=above}
import json, os

# ① 读输入
payload = json.loads(os.environ["IDEA_NOTE_INPUT"])

# ② 计算
total = payload["quantity"] * payload["price"]

# ③ 把结果打成一行 JSON
print(json.dumps(f"**合计：{total:.2f} 元**", ensure_ascii=False))
```
````

代码体固定分三段：**读输入 → 计算 → 打印一行 JSON**。中间一段是业务代码，头尾两段是固定套路。

### 5.2 信息行上的五个属性

| 写法（仅代表 5.1 完整形态的例子） | 作用 | 在哪讲 |
| --- | --- | --- |
| `python` | 用哪个解释器跑 | 6.1 |
| `in=params` | 数据从哪来 | 第 4 章 |
| `run=watch` | 什么时候跑 | 6.3 |
| `out=markdown` | 结果按什么类型渲染 | 第 7 章 |
| `result=above` | 结果显示在代码块上方还是下方 | 7.5 |

### 5.3 属性都可以省略

五个属性都有默认值，最短的可运行代码块就是一个什么都不写的普通代码块：

````markdown
```python
print("hello")
```
````

它照样能点运行按钮执行，区别是：没有 `in=` 就没有输入；没有 `out=` 就不产生行内结果卡片，输出只显示在运行输出面板里；没有 `run=` 就只能手动运行。

## 6. 运行：用什么跑、什么时候跑


### 6.1 支持哪些语言

信息行最前面的语言标识决定了用哪个运行器。内置支持这些：

| 运行器 | 围栏主标识 | 别名 | 默认命令 |
| --- | --- | --- | --- |
| Python | `python` | `py`、`python3` | macOS/Linux 为 `python3`，Windows 为 `python` |
| Node.js | `node` | `js`、`javascript`、`mjs` | `node` |
| Ruby | `ruby` | `rb` | `ruby` |
| Perl | `perl` | `pl` | `perl` |
| Bash | `bash` | `sh`、`shell`、`zsh` | `bash` |
| PowerShell | `powershell` | `ps1`、`pwsh` | `powershell` |

运行器可以在设置里禁用、改命令，也可以自己加。**一个组件到底能不能跑，最终取决于当前设备的设置和已安装的解释器。**

`mermaid`、`input`、`output` 是保留标识，不能当可运行语言用。

### 6.2 代码在什么环境里执行

- **在你自己的电脑上真实执行**，不是浏览器沙箱。
- 工作目录：已保存的笔记用笔记所在目录；未保存的草稿用当前工作区目录。
- 输入带来的环境变量会覆盖运行器配置里的同名变量。
- 默认超时 **30 秒**，可按运行器修改。
- 默认最大输出 **200 KiB**，可在设置里改。**输出一旦被截断，结构化结果就不再解析了。**
- 执行模型很简单：一条解释器命令 + 一个临时代码文件。没有 stdin，也没有 TTY。
- 需要交互输入、长期驻留、`sudo`、起服务、或者「先编译再运行」的场景，请改用「在终端运行」。

### 6.3 什么时候自动运行：`run`

| 值 | 行为 |
| --- | --- |
| `manual` | 只有点运行按钮才跑——**这是默认值** |
| `watch` | 绑定的 `input` 参数一变就自动跑 |
| `open` | 每次打开（或重新打开）这篇笔记时自动跑一次 |

多个自动触发器可以用 `+`、`|` 或空格组合：

```text
run=watch+open
run=watch|open
run=watch open
```

也可以把属性重复写：

```text
run=watch, run=open
```

几条关键行为，尤其是 `watch`：

- **`run=watch` 只对 `in=<input 块 id>` 有效**，它不监听 Markdown 表格和文件内容的变化。
- `watch` 有 **300 毫秒防抖**，连续拖滑块时只会执行最后一次计划任务。
- `run=open` 在**同一次打开期间只触发一次**。切换视图模式、刷新编辑器扩展都不会重复触发；关掉笔记再打开才会再跑。
- 只读模式下不执行任何 `watch` / `open` 自动运行。
- `run=manual` 会**清掉它左边已经解析到的自动触发器**。属性从左到右解析，所以别混写含义冲突的顺序。

老写法（新文档统一用 `run=watch` 就好）：

```text
watch          # 等同于 run=watch
watch=true     # 等同于 run=watch
watch=false    # 移除 watch
```

### 6.4 运行前的确认

手动运行永远由代码块上的运行按钮发起。开启「运行前二次确认」时：

- 手动运行：每次都问；
- 自动运行：**每个应用会话首次触发时问一次**，允许之后本会话内不再重复问；
- 同时打开多个 `run=open` 块时，它们排队共享同一次授权；
- 拒绝授权后，当时排队的自动运行就作废了，不会延迟到以后补跑。

### 6.5 重跑与「结果身份」

运行记录是按 **「文件路径 + 代码内容哈希」** 关联到代码块的。这个设计带来几个需要知道的后果：

- 同一个代码块重跑会替换旧记录；旧进程还在跑的话会先被停掉。
- **改了代码内容，旧结果就不再属于新代码了。**
- **两段源码完全相同的代码块会共享同一个结果身份。** 一篇笔记里需要两个独立结果时，让源码有点区别（比如加不同的注释）。
- 运行记录最多保留 50 条，且只在内存里。

## 7. 输出：把结果送回笔记

脚本跑完了，怎么让结果显示成表格、图表而不是一坨日志？答案是一个很简单的约定：**用 stdout 输出一行 JSON。**

只有代码正常结束、**退出码为 `0`** 时，系统才会去解析结果。解析只看 stdout；stderr 照常显示在运行面板里，但不参与结果协议。

### 7.1 方式一（推荐）：写了 `out=` 就直接输出数据

围栏上写了 `out=<类型>` 时：

1. stdout 前面可以随便打日志。
2. **最后一个非空行**必须是一个完整、合法、**单行**的 JSON 值。
3. 这个 JSON 值就是该类型的 `data`，不用再包一层。

```python
print("正在计算……")
print(json.dumps({"columns": ["A"], "rows": [[1]]}, ensure_ascii=False))
```

### 7.2 两种最常见的输出错误

**错误一：多行 JSON。**

```text
{
  "columns": ["A"],
  "rows": [[1]]
}
```

系统按行取最后一个非空行，而这里最后一行只有一个 `}`，不是完整 JSON。

**错误二：字符串没做 JSON 编码。**

```python
# 正确：最后一行是 "hello"（带引号）
print(json.dumps("hello", ensure_ascii=False))

# 错误：最后一行是 hello，不是合法 JSON
print("hello")
```

记住一句话就够了：**最后一行必须能被 `JSON.parse` 直接吃下去。**

### 7.3 方式二：让输出自我描述（`out=auto` 或不写 `out=`）

渲染成什么类型要等脚本跑起来才知道时，就在**任意一个独立的 stdout 行**输出这样一个包装对象：

```json
{"idea_note_result":{"type":"text","data":"hello"}}
```

通用结构：

```json
{
  "idea_note_result": {
    "type": "<输出类型>",
    "data": "<该类型要求的数据>"
  }
}
```

规则：

- 每个候选包装对象必须独占一行，且那一行本身是完整 JSON。
- 普通日志、非 JSON 行、不含 `idea_note_result` 的 JSON 行都会被跳过。
- 输出了多个形态正确的候选时，**最后一个生效**，并在最后统一校验它的 `type` 和 `data`。所以别在正确结果后面再输出一个残缺的 `idea_note_result`。
- 不写 `out=` 时，一个包装对象都没有也不算失败，只是不会出现行内结果卡片，普通输出照常显示在运行面板里。

**`out=auto` 和不写 `out=`，用的是同一套包装对象格式，区别只在「这个块在笔记里有没有位置」：**

| | 不写 `out=` | `out=auto` |
| --- | --- | --- |
| 运行前 | 没有占位卡片 | 显示「尚未运行」占位卡片 |
| 运行输出面板 | 每次运行都会弹出来 | 不弹（结果在笔记里有位置） |
| 没输出包装对象 | 不算错，安静收场 | 报错 `out=auto 没有返回 idea_note_result` |

所以：**临时跑一段脚本看输出**就不写 `out=`；**做一个渲染类型随参数变化的组件**就写 `out=auto`。

Python：

```python
result = {
    "idea_note_result": {
        "type": "table",
        "data": {"columns": ["项目", "值"], "rows": [["状态", "正常"]]},
    }
}
print(json.dumps(result, ensure_ascii=False, separators=(",", ":")))
```

JavaScript：

```javascript
const result = {
  idea_note_result: {
    type: "markdown",
    data: "**状态：正常**",
  },
};
console.log(JSON.stringify(result));
```

> 顺带说明协议里「合法 JSON 值」的范围：`null`、布尔值、有限数字、字符串、由 JSON 值组成的数组、属性值仍是 JSON 值的对象。`NaN`、`Infinity`、函数、`undefined`、日期对象、循环引用都不行，脚本要先自己转换。

### 7.4 七种输出格式

| `out` / `type` | `data` 的形态 | 渲染成什么 |
| --- | --- | --- |
| `text` | string | 等宽预格式化纯文本 |
| `table` | `{columns: string[], rows: JsonValue[][]}` | 表头可点击排序的表格 |
| `json` | 任意合法 JSON 值 | 两空格缩进的 JSON |
| `mermaid` | string | Mermaid SVG 图表 |
| `html` | string | 消毒后的静态 HTML |
| `image` | 非空路径字符串，或非空路径字符串数组 | 一张或多张图片 |
| `markdown` | string | 渲染后的 Markdown |

#### `text`

````markdown
```python {out=text}
import json
print(json.dumps("第一行\n第二行", ensure_ascii=False))
```
````

保留内部换行和空格，尾部空白会被去掉。内容用 `textContent` 写入，**不解析 HTML**。

#### `table`

```json
{
  "columns": ["列名1", "列名2"],
  "rows": [
    ["值1", 10],
    ["值2", 20]
  ]
}
```

约束（这几条最容易出错）：

- `columns` 必须是**字符串**数组。
- `rows` 必须是数组，每个 row 也必须是数组。
- **每一行的长度必须和 `columns` 完全一致。**
- 每个单元格必须是合法 JSON 值。
- **不支持把行写成对象**（如 `{"列名1": "值1"}`），要按列顺序转成数组。

````markdown
```python {out=table}
import json
result = {
    "columns": ["项目", "数量", "有效"],
    "rows": [
        ["键盘", 2, True],
        ["耳机", 1, False],
    ],
}
print(json.dumps(result, ensure_ascii=False))
```
````

渲染行为：点击表头排序，首次升序、再点降序；某列的非空值都能转数字就按数字排，否则按本地化字符串排；`null` 显示为空；数组和对象显示成紧凑 JSON；布尔显示为 `true` / `false`。

#### `json`

````markdown
```python {out=json}
import json
print(json.dumps({"ok": True, "items": [1, 2, 3]}, ensure_ascii=False))
```
````

用两空格缩进展示，适合调试、配置预览和层级数据。它不生成可折叠树，也不会把字符串再当 JSON 解析一次。

#### `mermaid`

````markdown
```javascript {out=mermaid}
const diagram = `graph LR
  A[输入] --> B[处理] --> C[输出]`;
console.log(JSON.stringify(diagram));
```
````

- 返回的是 **Mermaid 源码**，不是 SVG 字符串。
- 系统异步渲染成 SVG，源码首尾空白会先去掉。
- 语法错误会显示 Mermaid 自己的错误信息。

#### `html`

````markdown
```python {out=html}
import json
html = '<div style="padding:8px"><strong>完成</strong></div>'
print(json.dumps(html, ensure_ascii=False))
```
````

- HTML 先经 DOMPurify 消毒再插入页面，`<script>`、内联事件处理器等可执行内容会被删掉。
- 这是**静态展示格式**，不能依赖页面脚本、宿主 DOM 操作或组件内部状态。
- HTML 里的图片路径会按当前笔记位置转换成可显示地址。
- 需要交互？把交互放进 `input` 块，再用 `run=watch` 重新生成 HTML。

#### `image`

`data` 是一个路径字符串：

```json
"./chart.png"
```

或一个路径数组：

```json
["./chart-1.png", "./chart-2.png"]
```

- 字符串必须非空；数组也必须非空，且每项都是非空字符串。
- 支持相对当前笔记目录的路径和绝对本地路径。
- 也支持 `http:`、`https:`、`data:`、`blob:` 等可显示地址。
- GitHub 的 `blob` 图片链接会自动转成 raw 地址。
- 每个路径同时用作图片的 `alt` 文本。
- 协议只校验路径形态，**不保证文件存在**；加载失败由图片元素自己表现。

````markdown
```python {out=image}
import json
print(json.dumps(["./chart-a.png", "./chart-b.png"], ensure_ascii=False))
```
````

#### `markdown`

````markdown
```python {out=markdown}
import json
result = "## 汇总\n\n- 成功：3\n- 失败：0"
print(json.dumps(result, ensure_ascii=False))
```
````

- 由独立的 Markdown 渲染器生成 HTML，支持标题、列表、强调、链接、图片、代码等常规能力。
- 允许原始 HTML，但结果仍会经过消毒。
- 链接会自动识别；普通换行不会强制变成 `<br>`。
- 图片路径相对当前笔记解析。
- 结果里的可运行代码块**不会继续执行**，那只是渲染内容。

### 7.5 结果显示在哪里

`result=above`（默认）把结果放在代码块**上方**，这样参数控件和计算结果挨在一起，代码退到后面；想按「代码 → 结果」的顺序阅读时写 `result=below`。

行内结果卡片的行为：

- **写了 `out=<类型>` 或 `out=auto`** 的块，在运行前就显示一张「尚未运行」的占位卡片。
- **没写 `out=`** 的块默认没有占位，只有成功输出了有效的 `idea_note_result` 才出现结果。
- 卡片上会显示运行状态、耗时和输入摘要。
- `watch` 重算期间**保留上一次的结果**，避免拖滑块时结果闪空，状态显示为「运行中」。
- 新结果只有在运行成功且通过协议校验后才替换旧结果。
- 失败、超时、被停止、非零退出、协议错误时，写了 `out=`（含 `auto`）的卡片会显示错误；没写 `out=` 的普通代码块不会为此额外展开卡片，去运行面板看错误。

运行输出面板的行为：

- **没写 `out=`** 的块一运行就打开运行输出面板——它在笔记里没有展示位置，不弹面板等于点了没反应。手动点运行和 `watch` / `open` 自动触发一样会弹。
- **写了 `out=<类型>` 或 `out=auto`** 的块已经有行内展示位置，任何触发方式都不额外弹面板。
- 面板只在关闭状态下被弹开一次，且永远不会自动关闭；代码块右上角的「输出」按钮可以随时手动开关。
- 不管哪种情况，stdout / stderr 原文、命令、退出码、耗时、截断状态都保存在运行记录里。

### 7.6 结果能活多久

- 行内结果和运行记录**只在内存里**，不会自动写进笔记。
- 关闭文件会清掉该文件的运行记录；重启应用后结果不会作为 Markdown 内容恢复。
- 想持久化原始输出，可以在运行输出面板里把它插入到紧跟代码块的 `output` 围栏中。
- 注意：插入的 `output` 块存的是**原始 stdout/stderr 合并文本**，不是渲染后的 DOM。

## 8. 安全须知

### 8.1 代码是在本机跑的

可交互组件里的代码和普通可运行代码块一样，**以当前用户权限在本机执行**。它可以读写你有权限的文件、启动进程、访问网络，能干什么完全取决于脚本和操作系统环境。

所以：

- 只运行你信任的笔记里的代码；
- 从 Git、聊天、网上拿到的笔记，**尤其是带 `run=open` 的**，先审查代码再允许自动运行；
- 不要在字段或源码里硬编码密码、令牌、私钥；
- 会改文件、发请求、产生费用的脚本，保留运行确认；
- 只读模式能挡住自动触发，但**它不是操作系统级沙箱**。

### 8.2 文件输入的边界

`in=file:...` 和 `file` 字段自动载入的文件**必须在工作区内**，防止一篇笔记把工作区外的敏感文件直接塞进脚本。

但要理解这个限制的范围：它只约束组件的**自动文件载入器**；脚本本身在本机运行，仍然可以按自己的代码去访问别的路径。

### 8.3 输出的隔离方式

| 格式 | 处理方式 |
| --- | --- |
| `text` | 纯文本节点 |
| `json` | 先序列化成文本 |
| `table` | 单元格按纯文本渲染 |
| `html` / `markdown` | 最终经 HTML 消毒 |
| `mermaid` | 由专用渲染器转成 SVG |

当前不支持任意脚本型 HTML 组件，也不支持不受限的宿主页面事件。

## 9. 完整示例与设计建议

### 9.1 一个端到端的例子

这个例子覆盖了：命名参数块、数字滑块、下拉框、布尔值、文件字段、CSV 解析、`watch` + `open` 双触发、Markdown 输出、结果放在下方。

````markdown
```input {id=sales_report}
source:  file   = "./sales.csv" {as: csv, label: 数据文件}
minimum: number = 0 {slider: 0..1000, step: 10, label: 最低销售额, unit: 元}
region:  select = [全部, 华东, 华南, 华北] {default: 全部, label: 地区}
detail:  bool   = true {label: 显示明细}
```

```python {in=sales_report, out=markdown, run=watch+open, result=below}
import json
import os

payload = json.loads(os.environ["IDEA_NOTE_INPUT"])

# IDEA_NOTE_INPUT 过大时改从路径读；这里直接报错，便于第一时间发现。
if payload.get("_truncated"):
    raise RuntimeError(
        "输入负载过大，请从环境变量 source_path 自行读取 CSV"
    )

rows = payload["source_data"]
minimum = float(payload["minimum"])
region = payload["region"]
show_detail = payload["detail"]

selected = []
for row in rows:
    amount = float(row.get("amount", 0))
    if amount < minimum:
        continue
    if region != "全部" and row.get("region") != region:
        continue
    selected.append({**row, "amount": amount})

total = sum(row["amount"] for row in selected)
lines = [
    "## 销售筛选结果",
    "",
    f"- 记录数：{len(selected)}",
    f"- 销售额：{total:,.2f} 元",
]

if show_detail and selected:
    lines.extend(["", "| 产品 | 地区 | 金额 |", "| --- | --- | ---: |"])
    for row in selected:
        lines.append(
            f"| {row.get('product', '')} | {row.get('region', '')} | "
            f"{row['amount']:,.2f} |"
        )

print(json.dumps("\n".join(lines), ensure_ascii=False))
```
````

配套的 `sales.csv`：

```csv
product,region,amount
键盘,华东,1200
显示器,华南,2600
耳机,华北,680
```

### 9.2 命名习惯

- 参数块 id 用 `<业务>_<用途>`，例如 `loan_params`、`sales_filter`。
- 字段名用 `snake_case`，例如 `annual_rate`、`start_date`。
- 面向读者的中文放在 `label` 里，字段名保持适合脚本和环境变量的 ASCII。
- 同一篇笔记里的表格标题保持唯一。

### 9.3 参数怎么设计

- 连续区间用 `number` + `slider`，同时保留数字框供精确输入。
- 少量离散选项用 `select`。
- 开关语义用 `bool`，别用 `select = [是, 否]` 代替。
- 文件字段把 `as` 明确写出来，不要让读者猜。
- 用 `unit` 表达「元 / % / 年」等显示单位——注意脚本读到的仍是原始值，系统**不会**帮你换算。
- 给数字设合理的 `min` / `max` / `step`，防止一不小心触发巨大的计算量。

### 9.4 运行方式怎么选

- 算得快、没有副作用的纯计算，适合 `run=watch`。
- 仪表盘式的刷新适合 `run=open`，但要避免改文件、发消息、交易等副作用。
- 网络请求、耗时任务、有成本的操作，老老实实留在 `manual`。
- `watch` 脚本要做到幂等，因为用户可能疯狂改输入。
- 对外部数据做异常处理，面向用户的错误输出到 stderr，或者直接以非零退出结束。

### 9.5 输出格式怎么选

| 你想表达 | 用 |
| --- | --- |
| 一个结论 | `text` 或 `markdown` |
| 规整的行列数据 | `table`（行列长度务必严格一致） |
| 调试信息、层级数据 | `json` |
| 关系、流程 | `mermaid` |
| 小型视觉卡片 | 静态 `html` |
| 脚本生成的图表文件 | `image` |

最后一条：**不要用 `html` 去模拟需要脚本的表单**。参数交互一律交给 `input` 块。
